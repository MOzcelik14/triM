Sürüm Yayınlama Rehberi

Bu kılavuz, triM projesinde yeni bir sürümün hazırlanması, derlenmesi, test edilmesi, Git etiketinin oluşturulması ve GitHub Actions CI hattı üzerinden çoklu platform paketlerinin yayınlanması adımlarını belgeler.

1. Sürüm Numarasını Güncelleme

triM, Semantic Versioning (SemVer: MAJOR.MINOR.PATCH) standardını takip eder. Yeni sürüm için ilgili dosyalarda sürüm numarasını artırın:

# Cargo.toml kök dosyası [workspace.package] version = "1.2.0"

Ardından Cargo.lock dosyasını güncellemek için cargo check komutunu çalıştırın.

Meta veri dosyalarını güncelleyin:

  • io.github.mozcelik14.triM.metainfo.xml
  • README.md ve README.tr.md
  • docs/index.html ve docs/js/main.js

2. Doğrulama ve Testler

Etiket oluşturmadan önce çalışma alanındaki tüm 135+ testin, biçimlendirme kurallarının ve clippy denetimlerinin hatasız tamamlandığından emin olun:

# 1. Kod biçimlendirme kontrolü cargo fmt --all -- --check # 2. Uyarıları hataya dönüştüren Clippy denetimi cargo clippy --workspace --all-targets -- -D warnings # 3. Tüm çalışma alanı birim ve entegrasyon testleri cargo test --workspace

3. Git Etiketi (Tag) ve Push

Değişiklikleri commit edin ve imzalı/açıklamalı bir Git etiketi oluşturarak depoya gönderin:

git add -A git commit -m "chore: bump version to 1.2.0" git push origin master # Etiketi oluştur ve pushla git tag -a v1.2.0 -m "Release v1.2.0" git push origin v1.2.0

4. Otomatik CI / CD Dağıtım Paketleri

v* formatında bir etiket pushlandığında .github/workflows/release-linux.yml iş akışı otomatik devreye girer ve GitHub Releases üzerinde aşağıdaki paketleri derleyip yayınlar:

Paket Formatı Hedef Platform / Dağıtım
trim_x.y.z_amd64.debDebian, Ubuntu, Linux Mint (x86_64)
trim-x.y.z-1.x86_64.rpmFedora, RHEL, openSUSE (x86_64)
