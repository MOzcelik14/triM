# triM Engineering Roadmap (2-Month Cycle)

This document defines the upcoming engineering milestones and issue specifications for `triM`. Tasks are organized across four two-week sprints, with explicit technical scope, affected crates, and acceptance criteria.

---

## Sprint 1 (Weeks 1-2): Input Customization & Windowing Precision

### ISSUE-001: User-Configurable Keybinding Serialization & Conflict Resolver
- **Target Crates:** `trim-core`, `trim-ui`
- **Technical Scope:**
  - Replace hardcoded `ShortcutProfile` match arms in `crates/trim-ui/src/shortcuts.rs` with a serializable `KeymapConfig` lookup table (`HashMap<ShortcutAction, KeyBinding>`).
  - Persist custom keybindings to `$XDG_CONFIG_HOME/trim/keybindings.json`.
  - Implement a conflict detection pass that identifies duplicate `(Modifiers, Key)` assignments across global and timeline contexts.
- **Acceptance Criteria:**
  - Users can rebind any `ShortcutAction` via the shortcuts modal and persist changes across restarts.
  - Assigning a key combination already bound to another action triggers an explicit conflict warning and unbinds the previous action upon confirmation.
  - Unit tests verify roundtrip JSON serialization of all preset profiles (`Default`, `Premiere`, `DaVinci`, `FinalCut`) and custom overrides.

### ISSUE-002: Wayland Fractional Scaling & Subpixel Timeline Alignment
- **Target Crates:** `trim-ui`, `trim-app`
- **Technical Scope:**
  - Audit `pixels_per_point` scaling interactions in `crates/trim-ui/src/canvas.rs`, `ruler.rs`, and `track_header.rs` under Wayland compositors (`sway`, `Hyprland`, `KWin`, `Mutter`) at non-integer scale factors (`1.25x`, `1.5x`, `1.75x`).
  - Snap timeline clip rect coordinates, ruler tick lines, and playhead indicators to physical pixel boundaries (`(coord * ppp).round() / ppp`) to eliminate 1px vertical misalignment between `track_header` and `canvas` rows and blurry stroke rendering.
- **Acceptance Criteria:**
  - Track header row borders and timeline track lanes maintain zero vertical drift across 10+ tracks at `1.25x` and `1.5x` scale factors.
  - Automated UI layout test in `crates/trim-ui/src/lib.rs` asserts exact Y-coordinate parity across fractional `pixels_per_point` values (`1.0`, `1.25`, `1.5`, `2.0`).

## Sprint 2 (Weeks 3-4): Audio DSP & Non-Blocking Dialogs

### ISSUE-003: Master Bus Brickwall Lookahead Limiter
- **Target Crates:** `trim-media`, `trim-ui`
- **Technical Scope:**
  - Implement a stereo brickwall lookahead peak limiter in `crates/trim-media/src/audio.rs` at the final stage of `AudioMixer::mix_timeline_chunk`, replacing raw `sample.clamp(-1.0, 1.0)` hard clipping.
  - Use a circular delay buffer (`5 ms` lookahead at `44.1 kHz` = 220 stereo frames) with fast attack and exponential release envelope tracking, ceiling fixed at `-0.1 dBFS` (`0.9885`).
  - Expose real-time gain reduction (`dB`) metrics to `VuMeterState` in `crates/trim-ui/src/vu_meter.rs`.
- **Acceptance Criteria:**
  - Summing 4 simultaneous `0.0 dBFS` sine wave tracks produces zero hard-clipping harmonic distortion; output peak strictly respects `<= 0.989`.
  - VU meter UI renders a gain-reduction indicator bar when master bus limiting is active.

### ISSUE-004: Asynchronous Native File Dialogs Worker Bridge
- **Target Crates:** `trim-ui`
- **Technical Scope:**
  - Replace synchronous `rfd::FileDialog` calls in `crates/trim-ui/src/app/project_io.rs`, `media_actions.rs`, and `dialogs.rs` with background thread dispatchers communicating over `std::sync::mpsc::Receiver<FileDialogResult>`.
  - Prevent XDG Desktop Portal / GTK dialog modal invocation from blocking `eframe::App::update` frame redraws while a file picker is open.
- **Acceptance Criteria:**
  - Opening any file picker (Import Media, Open/Save Project, Export Path, Load LUT) does not stall the main UI render loop or halt background proxy/export progress bars.
  - Duplicate dialog invocations are guarded by an active state flag until the pending channel returns or is cancelled.

## Sprint 3 (Weeks 5-6): Interchange Parsers & Hardware Codec Probing

### ISSUE-005: FCPXML v1.9 & CMX 3600 EDL Import Parsers
- **Target Crates:** `trim-export`, `trim-core`, `trim-ui`
- **Technical Scope:**
  - Implement an XML reader in `crates/trim-export/src/fcpxml.rs` and an EDL line parser in `crates/trim-export/src/edl.rs` to support importing timelines generated by external NLEs (in addition to existing export support).
  - Handle rational frame-duration timestamps (e.g., `1001/30000s`, `100/2400s`), spine gap elements (`<gap>`), nested `<asset-clip>` audio/video roles, and missing media relinking prompts.
- **Acceptance Criteria:**
  - Exporting a multi-track `triM` project to `.fcpxml` or `.edl` and importing it back reconstructs clip `timeline_in`, `timeline_out`, `source_in`, and track assignments within `<= 1` frame tolerance.
  - Malformed XML/EDL files return structured `Result::Err` diagnostics without panicking.

### ISSUE-006: Runtime FFmpeg Hardware Encoder Capability Probing
- **Target Crates:** `trim-media`, `trim-export`, `trim-ui`
- **Technical Scope:**
  - Implement a startup background probe in `crates/trim-media/src/ffmpeg.rs` that executes `ffmpeg -hide_banner -encoders` and performs a 1-frame `null` encode test (`-f lavfi -i color=c=black:s=64x64:d=0.04`) for `h264_nvenc`, `hevc_nvenc`, `h264_vaapi`, `hevc_vaapi`, and `h264_qsv`.
  - Filter or disable unavailable hardware encoders in the `ExportDialog` UI (`crates/trim-ui/src/dialogs.rs`) and display the specific driver/device failure reason on hover.
- **Acceptance Criteria:**
  - Export dialog only enables hardware encoders verified to initialize on the host GPU/driver stack.
  - Probe runs asynchronously on application startup without delaying window creation.

## Sprint 4 (Weeks 7-8): GPU Compositing & Persistent Disk Cache

### ISSUE-007: GLSL Fragment Shader Preview Compositor (`glow`)
- **Target Crates:** `trim-ui`, `trim-media`
- **Technical Scope:**
  - Offload per-pixel preview operations (`ChromaKeyConfig`, `ColorWheelsConfig`, 3D `.cube` LUT trilinear interpolation, and affine `scale`/`rotation`/`pos_x`/`pos_y` transforms) from CPU loops in `crates/trim-media/src/video.rs` (`draw_clip_onto_canvas`) to an OpenGL 3.3 framebuffer (`glow::Framebuffer`) shader pipeline in `crates/trim-ui/src/monitor.rs`.
  - Upload raw decoded clip frames as GPU textures and composite tracks in a single multi-pass fragment shader.
- **Acceptance Criteria:**
  - CPU frame compositing time for a 2-track timeline with Chroma Key and Color Wheels enabled drops below `1.5 ms` per frame at `1280x720` preview resolution.
  - Visual output parity between the GLSL preview shader and `trim-export` FFmpeg filtergraph is verified via pixel-diff regression tests.

### ISSUE-008: Content-Addressed Persistent Waveform & Thumbnail Disk Cache Eviction
- **Target Crates:** `trim-core`, `trim-media`
- **Technical Scope:**
  - Bound the on-disk cache directories (`$XDG_CACHE_HOME/trim/waveforms` and `$XDG_CACHE_HOME/trim/thumbnails`) using a directory size scanner and `mtime`-based eviction pass on startup and project close.
  - Key cache filenames by `(canonical_path, file_size_bytes, mtime_secs)` SHA-256 digest to invalidate stale waveforms/thumbnails automatically when an external file is overwritten on disk.
- **Acceptance Criteria:**
  - Modifying a source media file in-place invalidates its cached waveform and thumbnail on reload.
  - On-disk cache directory size is automatically pruned when exceeding a configurable threshold (default `2 GB`).
